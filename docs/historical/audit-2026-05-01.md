## Critical gaps surfaced

Ranked by how much each blocks "the agent can do their job":

1. **Decision step 6 is not implemented.** No approve/reject/send-back UI, no `decisions` table, no removal from active queue. UC-001's main success scenario doesn't complete. Without this, the demo answers "can the system show what's wrong with a label?" but not "can an agent use this system to do their actual job?".

2. **Label image is not rendered in the detail view.** UC-001 steps 2, 5, 3b, 3c, 4b, 4c all assume the agent can see the label adjacent to the findings. The infrastructure (`image_path` is on `JobsTable`, files are in `data/incoming/`) exists; just nothing serving the file or rendering it.

3. **Gemini is not wired.** Stub returns identical canned data (`good-merlot`) for every unknown stem. Real bottles in `fixtures/labels/` will all show as Stone's Throw Merlot until Gemini is wired. This is the proximate reason that "dropping a real bottle in works" but doesn't tell you anything.

4. **Low-confidence collapses into needs_review verdict.** UC-001.3c wants confidence and verdict to be separable signals.

5. **Per-field `needs_application_data` is broken** (UC-001.4e). Zod throws on partial JSON; whole job goes to `failed`.

## Strengths surfaced

Worth capturing what the implementation got right, because it informs how aggressively to refactor:

- `verifyLabel` is regulation-grounded: real warning-text checks, real ABV format/tolerance per F-052 wine rule, brand normalization per F-030. Not a stub.
- The lifecycle/verdict split (separate axes) is exactly what was specified.
- Tests exist on the highest-bug-surface logic (`verification.test.ts`, `pair.test.ts`).
- The provider boundary is clean: `LabelProvider.analyzeLabel(imagePath) → ExtractedFields`. Wiring Gemini is a focused task that touches one file.
- The watcher's upsert-by-stem + late-sibling re-run is correct.

## Out-of-band code observations (not gaps; quality flags)

- `REGULATION_WARNING` is duplicated in `src/core/providers/stub.ts` and `src/core/verification.ts`. Move to `src/core/constants.ts` or similar; not urgent.
- `ApplicationData.alcoholContent` is `z.number()` (a float ABV) while extracted alcohol is a string ("13.5% alc/vol"). This is fine because `compareAbv` parses the string; just worth knowing for fixture authors writing `"alcoholContent": 13.5` not `"13.5%"`.
- `countryOfOrigin` is in `ApplicationData` but **not** in `ExtractedFields`. So Layer 2 cannot actually compare it — it returns `needs_review` with a "label image does not extract this field separately" message. Honest about the gap, but the gap exists. Add to `ExtractedFields` when wiring Gemini, or mark explicitly out-of-scope.
